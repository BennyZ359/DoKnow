# 把理念写进学习行为

DoKnow 的基本单元不是一段聊天，而是一轮带有证据的学习。用户为真实目标创建路线，每个知识单元依次经历：**学 → 练 → 实战 → 讲解 → 复盘 → 延迟回忆**。实践产物、错误、讲解与复盘都进入持久记录。

## 七个原则如何落实

| 原则 | 产品中的行为 | 可检验的证据 |
| --- | --- | --- |
| 知行合一 | 每个单元都有应用任务，理解之后必须做出来 | 代码、方案、观察记录或其他实践产物 |
| 学而时习之 | 复盘后的次日安排第一次回忆，成功后逐渐延长间隔 | 不看资料的回忆回答与历次复习记录 |
| 学思结合 | 学习阶段要求写下自己的理解，导师以追问引导思考 | 学习反思和用户自己的问题 |
| 学不可以已 | 完成一轮后仍保留复习任务，掌握程度可随错误下降 | 持续变化的掌握状态与复习日程 |
| 格物致知 | 用具体例子、可观察结果和反例检验概念 | 实战中的验证过程与适用边界 |
| 闻思修 | 讲解输入、独立思考与反复应用相连接 | 学习、练习、实战三个阶段的记录 |
| 教学做合一 | 先做，再用自己的语言教给一个初学者 | 包含原理、例子、边界的讲解稿 |

这同时吸收了检索练习、间隔学习、形成性评价和费曼式讲解的做法。它们是设计参考，不构成对个体学习效果的保证。

## 什么叫“学会”

点击“下一步”不等于掌握。学习笔记、练习正确性、实践评价、讲解评价和延迟回忆提供不同证据。服务器执行阶段约束，无法靠跳过前端页面完成一轮。练习失败保留在原阶段；回忆失败返回巩固练习，再次进行应用、讲解与复盘。

自评是线索，不是成绩。复习回答仍需评估，自评等级影响下一次复习间隔。第一次复习要等到次日，避免将刚看过内容的熟悉感当作长期掌握。

每轮复盘回答三个问题：

1. 这次实际做了什么，哪里卡住了？
2. 留下什么可复用的规则或笔记？
3. 与开始时相比，你的理解或做法有什么变化？

后两项用于检验“有无沉淀、有无不一样的体验”，并把结果存入个人知识库。

## 体验模式的边界

无模型密钥时，系统使用预设示例与规则提供完整流程。规则能判断选择题和部分结构性证据，不能可靠判断任意代码、论证或讲解的语义正确性。产品应持续说明这是体验模式，避免把文本长度包装为真正掌握。配置模型后，计划和评价由模型生成；模型评价仍需结合真实任务结果与人的判断。

AI 不执行用户提交的代码，不访问任意用户提供的 URL，也不代替真实环境中的实践。知识问答只基于已保存资料，找不到相关材料时明确说明不足，并附上实际来源。

## 下一步发展的判断标准

先观察用户是否完成一轮、失败后是否修正、延迟回忆是否成功、复盘笔记是否在新任务中被复用。再据此决定增加课程模板、题型、检索策略或教学工具。不能仅用聊天次数或页面停留时间替代学习效果。
