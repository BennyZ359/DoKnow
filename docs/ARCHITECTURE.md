# v0.1 架构与部署边界

## 一条完整链路

Vue 3 / TypeScript 前端通过 `/api` 访问 FastAPI。关系数据库持久保存目标、知识单元、活动记录与知识条目。模型服务层提供计划、教学、实践评价和讲解评价；文档服务负责解析、检索与带来源的资料问答。

教学采用 Workflow + Agent：确定性阶段转换由后端执行；导师通过 LangGraph 的 Observe → Think → Act → Reflect 选择教学策略。评分和阶段转换分离，模型不能任意修改学习状态。

## 本地与 Docker

本地使用 SQLite，没有数据库或模型服务依赖。Docker 使用 PostgreSQL 16，预装 pgvector 扩展，Redis 用于可选缓存，nginx 同源代理前端与后端。Docker 只把网页端口绑定到 `127.0.0.1`，数据库、Redis 和后端不直接暴露。

首版资料检索使用本地词法相关性与正文摘录。pgvector 扩展为后续嵌入检索准备，不代表首版已经生成或保存语义向量。当前不依赖 Docling / MinerU；使用 pypdf、python-docx 解析 PDF 和 Word，Markdown / 纯文本直接解析。不支持扫描件 OCR。

## 模型边界

`AI_PROVIDER=demo` 无需密钥。`openai` / `compatible` 使用配置中的兼容 Chat Completions 服务，通过结构化输出校验生成计划与评价。密钥只读取服务端环境变量，不返回前端。配置的模型故障必须向用户呈现错误，不能偷偷切回体验模式伪装为模型结果。

## 数据与安全

首版面向**一位本地学习者**。没有注册、登录、用户隔离、配额或面向公网的访问控制。要部署给多人使用，必须先完成认证授权、迁移机制、限流和运营监控。

所有用户内容按文本显示；模型文档上下文视作不可信资料。导入只接收限定格式和大小，不保存用户控制的文件路径。用户删除目标时清理关联单元和学习记录；独立知识条目可单独删除。

默认 SQLite 数据位于 `backend/data/doknow.db`。Docker 数据位于持久卷 `doknow_postgres_data`。数据库需要备份；缓存不作为学习记录来源。

数据库通过 Alembic 进行版本化迁移。只有完全匹配已知首版结构的无版本库才能登记基线；未知结构、较新版本和不完整关系拒绝升级。SQLite 明确开启写事务保证迁移失败回滚，PostgreSQL 使用事务迁移锁；当前实际验证环境仍为 SQLite。备份、校验和恢复到新文件的命令见 [数据管理](DATA_MANAGEMENT.md)。

写入请求可携带 `Idempotency-Key`。服务端以短事务取得操作租约，成功回执与业务数据在同一事务保存；重试返回同一次操作的结果。处理中的重复请求和不同内容复用标识会被拒绝。模型调用不占用 SQLite 写锁；进程在模型返回后、数据库提交前崩溃时，恢复可能重新请求模型，不能保证外部服务只计费一次。

浏览器将草稿和未确认操作保存在本地存储，按单元与阶段恢复；每个标签页保留自己的输入副本。提交确认后只清理与该次内容一致的草稿，不删除用户随后输入的文字。POST 成功结果先应用到页面，后续读取失败只提示同步；响应丢失则保留原操作标识供用户确认。草稿不跨设备同步，不属于数据库备份。复习状态在到期、页面恢复可见及定期同步时更新，服务端仍负责判断实际到期时间。

## 测试策略

后端测试覆盖阶段约束、正确与错误答案、学习记录、复习时间、知识导入、来源检索和模型故障。前端通过 TypeScript 检查与生产构建，再用浏览器验证完整学习流程、资料问答、刷新恢复和手机布局。Docker 静态配置检查与实际运行结果分别报告。
