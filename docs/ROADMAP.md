# DoKnow 后续路线

更新日期：2026-11-03。方向为个人本地版；优先级表示执行顺序，不是已经承诺的完成日期。本轮范围为 P1-1、P1-2，交付状态见 [PROGRESS.md](PROGRESS.md)。

P0-1 至 P0-5 已完成并通过远端 CI。P1-1、P1-2 已实现并通过本地回归；下面保留验收标准供后续修改时检查。下一批优先考虑 P1-3、P1-4。

## P0：本轮可靠性

### P0-1 数据库版本迁移

从目前的启动建表升级到明确的 schema 版本。新库可初始化，首版已有库可无损升级，重复启动幂等；未知结构或更高版本应报清晰错误。增加旧版数据升级测试，保留目标、单元、学习记录、知识条目、复习时间与关联关系。未经验证的库不可盲目标记版本。

验收：空库、首版库、当前版本重复启动、未知版本/结构拒绝、升级后学习闭环均有验证；说明 PostgreSQL 实测状态及数据恢复路径。

### P0-2 SQLite 备份与恢复

提供可用的命令行入口和中文操作文档。备份必须包含 WAL 中已提交的数据，并验证生成物可读取。恢复默认到新位置，拒绝覆盖现有文件；损坏备份应失败且保留原数据。

验收：备份后增改源库不改变备份；恢复副本保留记录和关系；损坏输入、错误路径和覆盖现有数据的操作有明确失败结果。测试全程使用临时文件。

### P0-3 草稿保存

按单元和阶段保存学习理解、实战产物、讲解稿、复盘、回忆及聊天草稿；对创建目标和笔记表单作一致处理。刷新、切换单元、提交失败仍能恢复；确认保存后仅清理该操作对应的草稿。草稿是浏览器本地内容，不宣称跨设备同步。

验收：两个单元不串稿；刷新恢复；成功清理与失败保留；过期响应不删除后写内容；本地存储受限或损坏时界面仍可用；明确本地保存的状态。

### P0-4 提交恢复与安全重试

区分“写入成功，页面同步失败”和“未确认写入结果”。POST 成功后先展示已保存结果，后续 GET 失败不诱导重复提交。使用持久幂等记录使同一操作的重试不会重复建目标、加笔记、调用模型或推进证据；不同内容复用同一操作标识须拒绝。仍由后端控制阶段转换。

验收：成功后 GET 故障、响应丢失后重试、重复与并发请求、重启后重试、同标识不同内容、模型失败后重试、已有无标识客户兼容。幂等记录与业务保存的事务边界要经过检查。

### P0-5 复习到期刷新

页面打开期间，到期时间、可提交状态和待复习数量能及时更新；页面从后台回到前台时同步服务器。防止计时器泄漏、重复请求和覆盖正在输入的内容。客户端时间只影响呈现，不能绕过服务端到期检查。

验收：测试时钟跨越到期点后自动解锁；恢复页面可见后徽章和列表更新；网络失败可恢复；未到期提交仍被后端拒绝。

## P1：下一轮个人学习能力

| 编号 | 工作 | 可验收结果 | 依赖 |
| --- | --- | --- | --- |
| P1-1 | 评价来源与历史 | 每次评价保留体验/AI 来源、模型和规则版本；界面可辨别结构检查与语义评价；旧记录显示来源未知，不伪造历史 | P0-1 |
| P1-2 | 题库与错题巩固 | 单元有多题与变式，失败后补练并保留尝试；服务端持有答案；不因背同一选项认定掌握 | P0-1、P1-1 |
| P1-3 | 学习计划可调整 | 编辑目标、每日时间、单元顺序或难度；已完成证据不被重新生成覆盖；课程变更可追踪 | P0-1 |
| P1-4 | 复盘与知识笔记管理 | 编辑、标签/搜索、导出可读 Markdown；删除目标后的独立笔记仍能阅读；导出不含配置或密钥 | P0-2 |
| P1-5 | 真实模型少量联调 | 在明确服务与费用范围下验证规划、导师、评价、检索；记录延迟、错误和格式兼容；失败不回退为假 AI 成功 | 用户模型配置与测试范围 |
| P1-6 | 启动与诊断 | 简化本地启动，报告端口冲突、配置缺失、数据库版本；日志能定位故障且不写密钥和整份学习资料 | P0 |
| P1-7 | 实际容器验证 | PostgreSQL、Redis、迁移、重启持久化和完整学习闭环在容器中通过；补自动化集成测试 | Docker 引擎 |
| P1-8 | 可维护性与无障碍 | 按真实状态边界拆分前端模块；键盘可操作、焦点和错误提示清晰；保留移动端和已有学习路径 | 按功能增量进行 |

当前仅推进 P1-1、P1-2。每次选择能形成完整体验的一组任务，其余 P1 项目不自动纳入本轮范围。

## 持续维护

修复缺陷时先复现，再增加能证明用户行为改善的测试。维护依赖锁定和 CI；不为了减少测试失败降低阶段约束或弱化资料校验。文档要区分“已实现”“模拟验证”“实际外部服务验证”。
